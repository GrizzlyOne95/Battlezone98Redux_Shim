[h1]Roadmap[/h1]

[b]Updated August 27, 2026[/b]

This is a rough roadmap for the Battlezone 98 Redux community patch / OpenShim / Extra Utilities / Campaign Reimagined work.

This is [b]not a promise that features will arrive in this exact order[/b]. Reverse engineering and runtime evidence determine whether a change is safe enough to ship.

[b]General priority:[/b]

[b]Fix crashes and broken stock behavior first, preserve Battlezone 1.5 behavior where Redux regressed it, improve multiplayer longevity, then expand the modding API and visual features.[/b]

[b]Important status note:[/b] the last public Workshop update was August 17. Items under "Changes Since the August 17 Workshop Update" describe current consolidated/development source intended for the next public cut, not necessarily the currently downloaded Workshop DLL.

Detailed compatibility/regression tracking now lives in:

[code]
Docs/COMMUNITY_REGRESSION_AUDIT_20260827.md
Docs/REDUX_HISTORICAL_REGRESSION_SWEEP_20260827.md
[/code]

The first captures Scott ("Herp")'s detailed technical reports and their current status. The second cross-checks official Redux patch notes, official known-issue posts, historical changelogs and later community technical reports so fixed stock bugs do not get reintroduced by OpenShim.

[h2]Changes Since the August 17 Workshop Update[/h2]

[h3]OpenShim - Stability / Compatibility[/h3]

[list]
[*] [b]Battlezone 1.5-style satellite visibility restored[/b] - satellite overview now respects the native illumination/visibility gate instead of visually revealing Ogre-rendered enemies across the map. Independent hidden-state owners are preserved.
[*] [b]TRN serialization repaired[/b] - supported 2.2.301 paths normalize mixed/corrupt newline forms and compatible UTF-8/CP1252 text, then emit deterministic CP1252 CRLF.
[*] [b]Non-English numeric-locale corruption repaired[/b] - presentation language remains intact while game numeric parsing uses dot-decimal semantics, preventing values such as 0.8 becoming 0.0 on affected locales.
[*] [b]Storefront-aware qualification/gating[/b] - Steam/GOG-specific patches require qualified executable/storefront identity instead of assuming all supported-looking binaries are identical.
[*] [b]IAT/loader race hardening[/b] - import patching and detach/shutdown behavior were reworked to reduce unsafe loader-lock work.
[*] [b]Native lifetime/shutdown hardening[/b] - stale pointers, thread handles, terrain proxies, HUD restore, headlight state and network optimizer paths were audited and tightened.
[*] [b]Deployment completeness[/b] - deployment carries matching patches.json with winmm.dll, verifies/backs up the installed pair and exposes stale mismatches.
[*] [b]Log-path sanitization[/b] - game-log path handling was hardened against unsafe/traversal components.
[*] [b]Quarantined attack-reveal hooks removed from production registration[/b] - the old experimental perceived-team attack-reveal path is [b]not[/b] a shipped compatibility fix. It must not be described as one.
[*] [b]Save/load lifecycle hardening[/b] - stale GameObject handles with invalid/empty object-pool state are rejected so recovery can run safely; this closes the reproduced native Inst4XMission save-load crash.
[*] [b]Destruction-chunk mission-transition lifetime fix[/b] - shim-owned Ogre chunk proxies are released before outgoing resource groups disappear.
[*] [b]Unscripted Instant Action AutoSave restored[/b] - engine-level AutoSave initializes again for single-player content without a Lua mission script.
[/list]

[h3]OpenShim - Rendering / Performance[/h3]

[list]
[*] [b]DX11 Enhanced FXAA 3.11 presentation pass[/b] - optional post-process anti-aliasing for Enhanced.
[*] [b]DX11 Enhanced light selection made more stable[/b] - dynamic-light candidates are selected more deterministically within the larger shader budget.
[*] [b]Stock destruction/live-fire submission amplification reduced[/b] - compatible smoke/effect/debris work is batched more coarsely; exact generic impact chunklets can share a dynamic batch while authored debris remains normal.
[*] [b]DX11 software-skin readback fix[/b] - software-skinned position/normal buffers receive CPU shadow storage instead of repeated GPU staging readbacks.
[*] [b]Finite craft bounds/culling restored and profiled[/b] - craft that behaved effectively unbounded can participate in renderer culling without a private visibility system.
[*] [b]Headlight/render hot paths reduced[/b] - repeated failed export lookups and redundant render/batch work were removed or memoized.
[*] [b]Sun whiteout / "flashbang" can be disabled[/b] - fullscreen sun-facing whiteout is independently suppressible while unrelated effects remain.
[*] [b]Renderer/profile ownership moved into OpenShim[/b] - canonical Retro/Redux/Enhanced state is owned by OpenShim rather than competing mod-side material-scheme changes.
[*] [b]Startup renderer backend selection reaches Ogre before initialization[/b] - Auto/DX9/DX11 preference is transported before Redux reads Ogre.cfg, with command-line override support.
[/list]

[h2]High Priority[/h2]

[h3]Community Regression / Historical Patch Audit[/h3]

The 2026-08-27 sweep produced several high-value regression gates that should not be lost:

[list]
[*] [b]Armory / Day Wrecker duplicate detonation[/b] - remote-only extra source-site damage remains open. Two-PC authority/creation/damage traces are required.
[*] [b]Historical Popgun MP duplication archaeology[/b] - Redux patch 2.0.131 explicitly fixed Popgun duplication in multiplayer. If pre/post binaries can be obtained, reverse-diff that fix before designing a new Day Wrecker/Splinter authority patch.
[*] [b]perceivedTeam victim retaliation / break-cover[/b] - capture/disguise writer parity is proven, but Scott ("Herp")'s actual complaint is victim AI failing to defend itself while disguised. Compare 1.5 vs Redux for ordinary craft, turrettank and turret using cannon hit/miss and sniper aggression.
[*] [b]CLI multi-parameter parser parity[/b] - destructive startup tokenization is proven; options taking multiple values still need 1.5-vs-Redux handler tracing. Preserve working controls such as renderer selection and -disablemods.
[*] [b]Legacy HGT smoothing / stock HG2 restoration[/b] - start with Great Pyramid (multdm29), because the final Redux patch explicitly removed smoothing there to restore the original stair-step terrain.
[*] [b]Shutdown phantom-process qualification[/b] - Rebellion's launch known-issues thread documented Redux sometimes remaining alive after shutdown. Add repeated clean-exit tests around current loader/thread/lifetime work.
[*] [b]AI path/subtask resumption invariant[/b] - the final Redux patch fixed AI wandering off-map after a subtask interrupted path following. New AI tuning must not regress it.
[*] [b]Pilot-loss decloak invariant[/b] - the final Redux patch fixed craft remaining cloaked after losing a pilot. Keep this separate from the future match-wide Cloak Disabled rule.
[/list]

[h3]GOG Workshop Compatibility[/h3]

Steam users receive Workshop dependencies through Steam; GOG users do not.

Goal: an [b]optional GOG Workshop bridge[/b] that identifies a missing item, asks the player, acquires/validates/stages it, refreshes content and resumes joining.

It must remain opt-in; OpenShim should not unexpectedly launch a downloader/helper.

[h3]Mod Dependency / Resource Isolation[/h3]

Redux does not provide a real dependency graph and can initialize resources from unrelated subscribed mods.

Goals:

[list]
[*] Missing-dependency detection.
[*] Installed-but-not-visible dependency diagnosis.
[*] Recursive dependency chains.
[*] Minimum OpenShim/EXU version requirements where useful.
[*] Selected-mod/dependency resource isolation.
[*] Prevent Ogre duplicate-resource failures from inactive/unrelated mods.
[/list]

A post-final-patch GOG report captured `Resource with the name TI_2_DETAIL_ATLAS already exists`; this remains a useful concrete isolation regression even where OpenShim currently mitigates some material conflicts.

[h3]Crash / Lifetime Work[/h3]

Crash/correctness bugs still outrank large new features.

[code]
reproduction
 -> crash signature / module + RVA
 -> native root cause
 -> narrowly scoped guarded patch
 -> runtime regression test
[/code]

Do not close broad "Redux crashes randomly" complaints globally; classify by signature.

Recycler, Factory, Armory, Constructor and generic Producer menus should eventually support scriptable categories/nested menus instead of only the stock flat layout.

[h3]Higher-Level Multiplayer Replication[/h3]

Object existence, distributed ownership, mission variables, UI/objectives, names, cameras and weapon state all have different replication rules.

Long-term host-authoritative helpers should cover proven cases such as:

[list]
[*] Spawn/remove.
[*] Shared mission/state variables.
[*] Names.
[*] Objective text/markers.
[*] Weapon/loadout changes.
[*] Custom synchronized events.
[*] Ownership-sensitive operations.
[/list]

Do not hide unknown network semantics behind a fake SyncEverything abstraction.

[h2]OpenShim Interface Improvements[/h2]

OpenShim now has a native UI framework, Options page, rewritten key-binding interface, startup renderer preference and canonical Retro/Redux/Enhanced render-profile ownership.

A longer-term organization could be:

[code]
OPENSHIM

Gameplay
Input
Video / Renderer
Multiplayer
Mods
Diagnostics
[/code]

Renderer page distinction:

[list]
[*] [b]Renderer backend[/b] - Auto / DX9 / DX11; startup/restart gated.
[*] [b]Render profile[/b] - Retro / Redux / Enhanced; runtime capability/resource gated.
[/list]

Raw Input is no longer an implementation-roadmap item: Redux's native WM_INPUT path is enabled/bridged. Remaining work is validation/presentation for sensitivity, focus transitions, high polling rates, smoothing/acceleration and ensuring raw/legacy paths never double-apply movement.

[h2]Environment / Terrain Runtime Control[/h2]

EXU can manipulate terrain materials/textures, fog, ambient/sun lighting, time of day, sky, gravity, shadows and visibility.

[b]DX11 Enhanced PSSM status:[/b] BZCC-informed shader improvements are merged into Campaign Reimagined. Native RE also found Redux sets roughly 128 m shadow far distance while receiver/material paths can extend toward ~250-256 m. An environment-variable-only validation override exists, but there is no normal user-facing production setting yet.

Longer term:

[code]
LoadEnvironment("MarsNight")
LoadEnvironment("EuropaStorm")
LoadEnvironment("LunaDay")
[/code]

[h2]Long-Term Goal[/h2]

The goal is not to replace Battlezone 98 Redux with a new engine.

The goal is to make the existing game:

[list]
[*] More stable.
[*] Easier to mod.
[*] Better behaved on modern systems.
[*] More consistent between Steam and GOG.
[*] Less dependent on external services remaining online forever.
[*] More faithful to proven Battlezone 1.5 behavior where Redux introduced regressions.
[*] Capable of supporting more ambitious community content than the stock scripting/API surface allows.
[/list]

OpenShim handles native engine access. Extra Utilities exposes supported functionality to Lua. Campaign Reimagined provides a real-world test environment. The community BZRNet work preserves multiplayer service compatibility and long-term viability.

The historical regression audit is now part of that goal: old fixed bugs and detailed community reports should remain documented as acceptance tests instead of being rediscovered years later.
